原机JDK为D:/DeepSeekHarnessData/jdk-21，SDK为D:/DeepSeekHarnessData/android-sdk。新机用实际路径设置JAVA_HOME和ANDROID_HOME；通过Android Studio SDK Manager安装组件与接受SDK许可。新开终端需重新设置环境变量或持久化为用户变量。

## 4. 克隆、恢复缓存、运行

以下在PowerShell执行，若无D盘可替换目录：

```powershell
gh auth login
git clone https://github.com/PLA0185/xunlian-2.git D:/OpenGYM-EX
Set-Location D:/OpenGYM-EX
git status --short
git log -3 --oneline
New-Item -ItemType Directory -Force artifacts/migration | Out-Null
gh release download phase-2.0.4 --repo PLA0185/xunlian-2 --dir artifacts/migration --pattern source-cache.zip --pattern signing-vault.json --pattern SHA256SUMS.txt
Get-FileHash artifacts/migration/source-cache.zip -Algorithm SHA256
Expand-Archive -LiteralPath artifacts/migration/source-cache.zip -DestinationPath .
Set-Location api
npm ci
Set-Location ../frontend
npm ci
npm run data:bootstrap
node ../scripts/data/validate-seed.mjs
npm test
npm run build:local
npm run dev -- --host 127.0.0.1 --port 5175
```

cache的SHA256应与下载的SHA256SUMS一致；bootstrap逐个核对原始来源SHA，不静默替换版本。命令在已解压目录重复运行时不要盲目覆盖文件，先核对本地改动。开发预览http://127.0.0.1:5175/；端口被占用可换。dev占用当前终端，另开终端做构建。

已有克隆先保留本地修改再git pull；不要reset丢改动。只把阶段备份推origin，若需研究上游可另外加alexpcosta/opengym为upstream。

bootstrap恢复2648原图/GIF、来源NOTICE和种子；会清除整库高清标记。未来高清包须在bootstrap后导入。来源下载不可用时使用这份锁定缓存，不能跳过哈希或用空白图冒充素材。

## 5. 原签名迁移与双端打包

先把旧电脑恢复口令安全带到新机，不放入聊天、命令参数、Git或Release。新机交互终端：

```powershell
Set-Location D:/OpenGYM-EX
$env:JAVA_HOME='D:/DeepSeekHarnessData/jdk-21'
$env:ANDROID_HOME='D:/DeepSeekHarnessData/android-sdk'
pwsh -NoProfile -File scripts/signing-migration.ps1 -Mode import -VaultPath artifacts/migration/signing-vault.json
pwsh -NoProfile -File scripts/build-release.ps1
python scripts/verify-apk.py
Set-Location frontend
npm run build:windows
Set-Location ..
node scripts/verify-windows.mjs artifacts/windows/OpenGymEX-2.0.6-portable.exe
```

导入脚本交互输入恢复口令，解密原keystore和密码，重新建立新机器可解密的DPAPI文件；不会默默覆盖不同签名。发布脚本默认发现原签名缺失即停止；`-AllowNewSigningKey`仅供明确创建全新身份，不能用于迁移现有App。

原证书SHA256必须为：

```text
100d6bb2cc70e95b8b203935bbdc62de4f15a5e478465c78aafd74e77d60285f
```

当前产物：`artifacts/OpenGymEX-2.0.6-personal.apk`与`artifacts/windows/OpenGymEX-2.0.6-portable.exe`。目录包入口`artifacts/windows/win-unpacked/OpenGymEX.exe`须携带整个目录。Android包名app.xunlian.personal、min26/target36，保持原签名和包名；升级必须递增versionCode。Windows用户数据目录AppData/Xunlian保持。

未来更新frontend/package.json和锁文件的version，以及android/app/build.gradle的versionName/versionCode。脚本按package版本命名产物，不再手改APK文件名。Debug签名不同不能冒充覆盖升级包。新机重构建字节哈希可能不同，须重新生成哈希并验证原证书。

下载已构建包可用：

```powershell
gh release download phase-2.0.6 --repo PLA0185/xunlian-2 --dir artifacts --pattern OpenGymEX-2.0.6-personal.apk --pattern OpenGymEX-2.0.6-portable.exe
```
