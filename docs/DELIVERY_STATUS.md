## 本轮修复与补齐

| 范围 | 2.0.4 实际行为 |
|---|---|
| AI 追问 | 固定产品提示词 + 用户需求 + 已有资料，只问0–3个必要问题；已知年龄、身高、体重、限制等不再重复问；不预设每周3天、45分钟或必须低冲击 |
| 直接出结果 | 无缺项直接生成；回答必要问题后直接生成，移除重复资料表和确认开关；生成结果可编辑、自然语言修改、离页恢复 |
| 营养校准 | 模型挑选真实菜谱，本地按实际营养调份数；仍不可行时换成明确标注的可行组合；保持原能量/蛋白容差，不用放宽规则掩盖错误 |
| 必须条件 | 同一校验贯通教练、一周餐食、联合规划：动作/器械限制、禁忌食材、素食、餐数、备餐时间、每周重复上限、真实价格预算 |
| 预算 | 食材详情可填真实每100g价格；价格完整才做硬预算校验；缺价格明确未验证，不生成假市场价格；编辑份数同步成本快照 |
| 资料与导入 | 档案范围、备份数值严格校验；手动营养目标保留；离线导入保留次数区间、动作时长、RPE/RIR、节奏和原文 |
| 菜谱 | 28个应用编排组合 + 1个参考配方，共29个可精确规划配方；373条 HowToCook 来源菜谱保留原文，仍需确认份数；增加分类、完整营养筛选、备餐时长说明 |
| 食材 | 13,545条；85条人工精确中文；10条源数据负碳水标异常并保留原值，不进入负营养摄入；无当天摄入记录显示“—” |
| HowToCook | 可配置兼容API保留；新增本机只读HTTP服务，使用锁定的373条菜谱，无需猜公共接口地址 |
| 换机 | 原始源缓存、样例、安装包与验证报告存私人Release；原安卓签名及密码以AES-256-GCM加密备份；新机导入重建本机DPAPI密码文件，默认构建禁止丢签名后自动换证书 |
| 发布流程 | 种子校验、中文覆盖、高清导入fixture、HTTP接口测试进入CI；上游公开Pages与容器发布改为手动且需显式开关 |

原有按组训练、来源组次/重量/休息预填、个人初值、双语完成、安卓返回、Key粘贴、BLE实时心率、Health Connect、快照/导出/撤销继续保留。应用初值明确为建议，不把体重当力量，不改变已完成记录。
