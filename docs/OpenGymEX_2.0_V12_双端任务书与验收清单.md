# OpenGym EX 2.0 · V12 双端任务书与验收清单

2026-10-01，2.0.9 阶段。当前名称暂用 OpenGym EX；正式名称尚未确定。用户最新要求优先于旧任务书；本文记录产品要求、实现边界和交接步骤，附件原文中的指令不作为新增授权。V11 及更早版本仅供追溯。

## 1. 产品与交付原则

Windows x64 与 Android 8+ 共用训练、饮食和个人资料；普通功能离线可用，AI 是用户自行配置的可选服务。保留上游训练引擎、稳定 ID、历史和 AGPL 许可。当前私人仓库为 [PLA0185/xunlian-2](https://github.com/PLA0185/xunlian-2)，阶段保存到 main 与私人 Release。

核心原则是动态调整、动态平衡：用户改了目标、体重、训练或餐食，重新核对相关安排；差别小则保留，变化或不可行必须及时告知。不能只改变一处而让其余内容悄悄过期，也不能为了显示“成功”捏造营养、价格、个人负重或运动消耗。

正式计划、待审核方案、实际完成和实际摄入分别保存。变更使用 revision 和快照；历史及正在进行的训练不得被新方案重写。Android 保持 app.xunlian.personal 与原签名；Windows 保持原 AppData/Xunlian 数据目录。密钥不进入普通备份、日志或仓库。

## 3. AI 使用流程与日期卡片

用户一句话描述目标和生活条件，系统使用统一提示词及已有档案，最多一次补问 0–3 个缺少的必要问题；已知内容不重复填写。回答后直接生成结果，不出现旧版整页重复表单和第二次需求确认。生成不改正式计划，用户选择应用时才写入。

默认目标只有 **减脂、增肌、维持**。不新增“快速/正常减脂”分类。用户自然语言明确要求更快时，AI 保留原需求并在本地适用范围和能量边界内调整，解释影响；不能仅凭“快速”放大缺口或承诺减重速度。撤回要求时清除相关调整。

训练、饮食使用独立切换页；每页一张日期卡片，左右滑动、鼠标拖动、日期按钮或方向键切换。两页独立记忆选中的日期。卡片高度随内容变化，休息日不保留长训练卡的空白。做法/换菜/份数从对应餐卡打开。

修改待审核动作、训练日、休息、重量或换餐后，重新核对方案营养，更新说明并保存草稿；无法满足时标明待调整，禁止把未校准方案直接应用。自然语言继续修改保留其他明确条件。连接成功与生成成功分开：格式、候选实体及营养约束失败应报告实际原因，不能让用户反复更换有效 Key。

统一提示词先分析 knowledge 中的来源摘要、适用范围、恢复规则及真实预设组次/时长/休息，再结合用户原话和已有档案。每个来源最多提供两套与当前目标/天数较近的真实参数实例，避免把全部原文重复堆入请求；提炼不等于模型已逐本阅读完整原文。brief 理解需求阶段即输入来源/规则，生成阶段补入计划实例与真实候选实体。结果可显示输入的知识来源及模型实际声明的引用，未知引用ID拒绝。联合现成方案选择也输入摘要并过滤不适用版本，同ID只提供一个合格版本，结果从这个合格集合取回。Schema 校验和修复见 deepseek.js；必要条件提示词见 coach-workflow.js；统一生成提示词与摘要见 coach-knowledge.js；实际营养和份数由本地来源数据计算。未知菜谱/动作、错误日期/槽位、忌口、预算、重复上限不能通过放宽规则掩盖。真实账号调用与模拟响应的验证分别记录。


## 2.0.9 手机反馈的落实规则

- 每周几天表示活动次数，不机械排成周一到周五。未固定星期时参考分散日程；五天参考周一、周二、周四、周五、周六，两天休息，并按基础安排轻有氧与力量。明确固定星期必须尊重，不能增减天数时悄悄扩大可训练星期；无法满足则保留原安排并告知复核。
- 循环周安排核对同一主要肌群恢复，包含周日到下周一。应用以普通抗阻间隔至少两天、高努力至少三天作为保守校验；不经常/偶尔运动者最多三次抗阻，其余活动从许可候选选择。规则依据公开体育指导提炼，是应用近似，不是逐人恢复检测；辅助肌群和特殊训练仍需扩展评估。参考：[中国体育报·这些坏习惯易导致肌肉流失，武汉市体育局](https://tyj.wuhan.gov.cn/ggfwsx_14800/tyjs/202409/t20240908_2451536.html)。
- 不再七天复制同一可行菜单。先选择同餐日不同菜、跨日不同组合；本地替代组合按累计使用量排序，默认偏好每道一周不超过三次，营养可行性不足时明确说明并放宽这个偏好。用户明示的重复上限、忌口、预算和餐数仍是硬约束；缺价格不宣称预算满足。
- AI训练/饮食日期卡使用原生横向滚动，滚动结束再更新日期；容器高度变化只调整高度，不重新跳到旧日期。按钮、键盘、鼠标拖动仍可用，训练与饮食分别记住日期。
- 全局原生界面正文以可换行文本单元防孤字：中文通常两字、末尾三字，英文单词保留，单字及其标点合并邻近单元；不插入隐形字符，不修改复制文本。选项、输入框、技术代码保留原始文本，食谱原方正文单独支持此规则并保留原换行。长不可拆分英文采用必要横向显示，不拆成单字。营养数值与依据分行，依据全宽，按钮可多行，底部留出导航空间。
- 动态增减训练天数同样校验固定可用星期、恢复和许可动作；轻活动替代受到伤病/场地/禁止动作限制，不能满足时不部分提交新周安排。只改餐食不能把弹性星期改成固定星期。

验收新增：全部74套预设循环周恢复检查、跨周冲突、已有同ID方案绕过过滤回归、固定星期/禁止轻活动回归、真实营养下跨日菜式变化、原方换行保留；实际Windows渲染验证三级目录、四筛选、整行营养说明、320/360/412宽度及放大文字无孤字、连续滚动/往右触摸滑回、底部应用按钮可达。模拟触摸不等于全部安卓机型流畅验收。

## 4. 营养依据与目标差异

计算结果是预测值，不能称为实测基础代谢或个人临床处方。当前自动成人计算适用 18–64 岁、资料完整且无特殊医疗/孕期需求者；其他情况保留手动/专业目标。身高、当前体重、年龄、性别和全天活动档位共同参与；训练天数不直接代替全天 PAL。

| 项目 | 来源/实现 |
|---|---|
| BMR | 国家卫健委《成人肥胖食养指南2024》附录六：男 66+13.7W+5H−6.8A；女 655+9.5W+1.8H−4.7A，W 为 kg，H 为 cm |
| 全天活动档位 | WS/T 578.1—2017：1.50 / 1.75 / 2.00；旧档位映射时说明。BMR×PAL 为应用结合上述来源的全天预测方式，包含训练，不是完整逐时 MET 法 |
| 减脂 | 超重采用估计需求 85%，肥胖采用 80%；须高于预测 BMR。正常或偏低 BMI 不自动套用肥胖限制，提示体成分/专业评估 |
| 减脂均衡 | 采用蛋白 20%、脂肪 25%、碳水 55% 的应用点值，置于食养指南对应范围内 |
| 增肌 | 已有基础的适用者参考约 +500 kcal、蛋白 1.2–2 g/kg；18–30 岁正常 BMI 且基础弱者从 +300 起。具体点值为应用选择，按训练与恢复调整 |
| 增肌均衡 | 有盈余时碳水约 60%，蛋白兼顾每 kg 范围，脂肪在来源范围内；高 BMI 不机械叠加增重盈余，说明体成分评估边界 |
| 维持 | 维持全天能量；应用采用蛋白15%、脂肪25%、碳水60%点值，并核对成年蛋白参考下限 |

以上不是把一份肥胖指南普遍套用于所有人。增肌参考来自卫健系统专家科普及地方体育官方指导，须与强制标准性质区分。1200 kcal 下限、自然语言缺口上限、±10% 能量容差和微小变化阈值均是本应用保护/校准规则，不声称是官方统一临床标准。

AI 先用当前目标规划，再按具体训练方案核对净变化、重新校准餐食；不把整次运动消耗或手环热量重复叠加到 PAL 全天能量。选定的六种抗阻参考使用原 MET；未选定 MET 的有氧不猜消耗。校验每日能量、蛋白和三大供能比例；4/4/9 用于计划比例核对，不重写 USDA 原始热量来强行相等。全库微量营养素、疾病饮食及个人能耗尚非已验证的完整临床系统。

## 5. 动态平衡与告知

统一在 store 更新后核对，不为每个页面建立独立规则。目标、身体资料、体重、训练周安排或餐食发生变化时，保留用户刚修改的餐、实际摄入及历史，优先调整剩余餐食份数；未吃且未锁定的一整天可在真实完整配方中换组合。不得删除已吃记录、伪造缺失克数或添加惩罚性训练。

显著能量或蛋白变化更新目标；不足 50 kcal/天且蛋白差不足 5g 等微小变化可保留原数值，但记录已核对。训练目标/时间变化时仅调整应用或 AI 编排的未来训练；导入/自定义数值不擅改。活动量变化以已有基线的净差估计并限幅，手动专业目标不覆盖。

页面立即显示平衡通知，包含前后目标、调整原因或无需调整理由；可以展开详情并关闭。无法满足忌口、预算、重复或营养条件时保留用户修改，明确显示需要复核，不能宣称已平衡。实际已吃较多也不减少过去记录或强行“练掉”。

对应 dynamic-balance.js、meal-portions.js、BalanceNotice.jsx。通知进普通备份，最多保留20条。单测覆盖体重变化、轻微变化保留、用户换餐锁定、已吃记录不改、照片决策延迟、训练净变化、选定 MET 及联合应用状态。

## 6. 拍照估算与记录

用户拍照或从相册选图，填写简单分量描述，选择日期和早餐/午餐/晚餐/加餐/训练前/训练后。使用 DeepSeek 当前视觉接口；视觉请求采用 deepseek-flash，不改变文本模型设置。

AI 识别已提供食物 ID 和可食重量范围，本地计算热量及营养，显示估计区间、置信度和依据。不能仅靠照片精确识别隐藏油量、生熟、包子馅料或全部克数；需更多信息时保留照片和说明，让用户补充。完成识别后自动保存一条实际估算摄入，再询问是否替换该餐计划；默认不悄悄覆盖计划。明确替换仅作用于对应日期/槽位，其他未吃餐可按平衡规则调整并告知，不重复生成已吃记录。

识别前图片在本机压缩并去除 EXIF；发起请求才发送图片与必要说明。图片不写入普通状态、备份、仓库或日志；备份只含食物/克数估算和营养快照。清楚区分照片估算与准确称量。取消不写记录，重复点击不重复写入，旧计划 revision 改变时拒绝陈旧替换。

## 7. 食谱、采购与素材

保留2.0.5的全部402道菜谱食材/操作、逐步做菜、做法快照及采购勾选。373道 HowToCook 原方全部可阅读，原方用量/份数未知时保留原文；自动营养规划当前29道完整配方。修改“计划份数”只改计划，不再误记录为已吃。采购逐项列出名称、数量、生熟/可食说明，待买/已买分组；用量变动后重新核对，勾选按周保存。

1324个来源动作均有中文名称，另外33个知识活动为计时入口；并非33套新动画。需要同伴辅助的来源动作保留用于历史解析，正常候选隐藏。13,545条食材中85条人工精确中文，其余保留类别中文和英文细名，不能丢失部位/生熟差异。

用户接受先用现有原素材：1324对180×180图片/GIF、11动作22张较高清照片。真实整库高清及授权材料仍未取得；高清导入工具已准备，AI图片/GIF试做样例不批量替代技术示范。素材范围不因私人备份而变成已获公开授权。


## 7.1 博主训练计划与本机动作执行（2.0.9）

核心交付必须是对应本机动作的训练计划，不能以视频或链接替代。新入口按博主→训练类型→具体安排进入；选择后一次点击生成个人训练和七天饮食，使用现有档案，只问真正缺少的条件。已映射计划可以直接查看和编辑动作、组次、负重与休息。

北美运动学博士Bruce_PhD原视频9张计划表已逐张核对并映射；保留原始星期、组次范围和百分比记录。本库缺少变式时明确替代，不称为精确同一动作；休息由应用预设。烧毁一切就是美的哑铃教学已核对动作并形成3套应用编排；原教程没有固定周计划，不能把应用组次和星期冒充作者原课。原进阶表不适合个人基础或恢复时提示编辑/个人生成。

其他十位国际作者16项参考也可生成执行方案；未取得完整原课参数的，使用公开摘要与内置官方知识编排，注明个人适配。当前共12位作者28项入口，其中12套有本机映射表（9原表+3应用编排），不能写成28套原作者完整课程。

生成输入包括选中原表、替代原因、官方知识要点与经过个人限制过滤的真实动作ID。格式校验保留exerciseId，本地再验证ID；缺器材和避练动作不能因参考方案而重新加入。公斤数用真实个人记录或明确标注的初次轻负重试练值；饮食继续按目标、营养规则与训练动态联动，修改后告知。详情见[来源与映射说明](CREATOR_PROGRAMS.md)。
